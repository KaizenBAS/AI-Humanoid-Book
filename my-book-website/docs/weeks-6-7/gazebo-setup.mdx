# Gazebo Simulation Environment Setup

## Introduction to Gazebo

Gazebo is a 3D simulation environment that provides realistic physics simulation, high-quality graphics, and convenient programmatic interfaces for developing and testing robotic applications. It's widely used in the robotics community for algorithm development, robot testing, and validation before deployment on physical robots.

## Installation and Setup

### Installing Gazebo

ROS 2 distributions typically come with Gazebo Fortress (Garden in newer distributions). You can install it with:

```bash
# Install Gazebo and ROS 2 Gazebo interface
sudo apt install gazebo libgazebo-dev
sudo apt install ros-$ROS_DISTRO-gazebo-*

# Source environment
source /usr/share/gazebo/setup.sh
```

### Verifying Installation

```bash
# Test Gazebo
gz sim

# Test with ROS 2
ros2 run gazebo_ros gazebo
```

## Gazebo Architecture

### Core Components

- **Gazebo GUI**: Visual interface for interacting with simulations
- **Gazebo Server**: Headless physics simulation engine
- **Plugins**: Extend functionality (sensors, controllers)
- **Model Database**: Repository of pre-built robot models

### ROS 2 Integration

Gazebo integrates with ROS 2 through the `gazebo_ros` package, which provides bridges between Gazebo's native interface and ROS 2 topics/services/actions.

## Basic Gazebo Concepts

### Worlds

World files define the simulation environment:

```xml
<!-- example_world.sdf -->
<sdf version='1.7'>
  <world name='default'>
    <!-- Include empty ground plane -->
    <include>
      <uri>model://ground_plane</uri>
    </include>
    
    <!-- Include sky -->
    <include>
      <uri>model://sun</uri>
    </include>
    
    <!-- Add a box -->
    <model name='box'>
      <pose>0 0 0.5 0 0 0</pose>
      <link name='link'>
        <collision name='collision'>
          <geometry>
            <box><size>1 1 1</size></box>
          </geometry>
        </collision>
        <visual name='visual'>
          <geometry>
            <box><size>1 1 1</size></box>
          </geometry>
          <material>
            <diffuse>1 0 0 1</diffuse>
            <specular>1 1 1 1</specular>
          </material>
        </visual>
      </link>
    </model>
  </world>
</sdf>
```

### Models

Models represent robots and objects in the simulation:

```bash
# List available models
gz model --list

# Spawn a model
gz model --spawn-file /path/to/model.sdf --name my_robot --model-name my_robot

# Or with ROS 2
ros2 run gazebo_ros spawn_entity.py -file /path/to/model.urdf -entity my_robot
```

## Running Gazebo with ROS 2

### Basic Integration

```bash
# Start Gazebo with ROS 2 interface
ros2 launch gazebo_ros empty_world.launch.py

# Or with a specific world
ros2 launch gazebo_ros empty_world.launch.py world_file:=/path/to/world.sdf
```

### Spawning Robots

```bash
# Spawn a robot from URDF
ros2 run gazebo_ros spawn_entity.py -topic robot_description -entity my_robot

# Or with a launch file
<node pkg="gazebo_ros" exec="spawn_entity.py" args="-topic robot_description -entity my_robot -x 0 -y 0 -z 1" />
```

## Gazebo Plugins

### Sensor Plugins

Gazebo includes various sensor plugins that publish ROS 2 topics:

- **Camera sensors**: `camera`, `depth_camera`, `multicamera`
- **LIDAR**: `gpu_lidar`, `ray`
- **IMU**: `imu`
- **GPS**: `gps`

### Controller Plugins

```xml
<!-- Example of a differential drive controller in URDF/SDF -->
<gazebo>
  <plugin name="diff_drive" filename="libgazebo_ros_diff_drive.so">
    <left_joint>left_wheel_joint</left_joint>
    <right_joint>right_wheel_joint</right_joint>
    <wheel_separation>0.3</wheel_separation>
    <wheel_diameter>0.15</wheel_diameter>
    <command_topic>cmd_vel</command_topic>
    <odometry_topic>odom</odometry_topic>
    <odometry_frame>odom</odometry_frame>
    <robot_base_frame>base_link</robot_base_frame>
  </plugin>
</gazebo>
```

## Gazebo ROS Packages

### Key Packages

- `gazebo_ros`: Core ROS 2 interface to Gazebo
- `gazebo_plugins`: Collection of ROS 2-aware Gazebo plugins
- `gazebo_dev`: Development headers and tools
- `ros_gz`: Bridges between ROS and Gazebo garden/fortress

## Common Commands

```bash
# View available topics
ros2 topic list | grep gazebo

# Check Gazebo status
ros2 service list | grep gazebo

# Reset simulation
rosservice call /gazebo/reset_simulation std_srvs/Empty

# Pause/resume
rosservice call /gazebo/pause_physics std_srvs/Empty

# Unpause
rosservice call /gazebo/unpause_physics std_srvs/Empty
```

## Performance Tips

### Optimization

- Reduce rendering quality in headless simulations
- Limit update rates for sensors not actively used
- Minimize physics complexity where possible
- Use appropriate collision geometry (simpler than visual geometry)

### Best Practices

- Use dedicated machines for complex simulations
- Monitor CPU/GPU usage during simulation
- Implement proper error handling when Gazebo isn't available
- Separate simulation from real robot code paths

## Troubleshooting

### Common Issues

1. **Model spawning failures**: Check joint names match URDF
2. **Plugin load errors**: Verify plugin libraries are installed
3. **Performance issues**: Reduce world complexity or sensor rates
4. **Networking**: Ensure ROS 2 and Gazebo networks are configured properly

### Debugging

```bash
# Enable extra logging
export GAZEBO_VERBOSE=1

# Check for plugin issues
gz plugin --verbose

# Monitor topics
ros2 topic echo /gazebo/model_states
```
